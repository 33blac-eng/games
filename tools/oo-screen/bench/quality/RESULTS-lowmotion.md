# bench/quality — стеля бітрейту для малорухомого вмісту, R3 (СИМУЛЯЦІЯ)

> **Симуляція, не вимір на реальному ПК і не MS MFT.** Змішана офісна година з `workloads.py` (60 с, 1080p30; простій 45 %, набір 25 %, відео в куті 15 %, скрол 10 %, перетягування 5 %), x264 як у `RESULTS-workloads.md`. Політика (`internal/contentmode.Capper`, прапорець агента `-lowmotion-cap`, типово ВИМКНЕНО) бачить лише кадри (частка змінених блоків 16×16), не мітки сценарію. Байти кадру беруться з енкоду на тій ставці, яку обрала політика (8M / 4M / 2M); перехідний процес енкодера при зміні ставки посеред потоку **не моделюється**. Відтворення: `python3 bench/quality/lowmotion_run.py`.

## Політика

- рух кадру ≥ 25 % екрана → повна ціль (8M) миттєво;
- режим Video (≥ 10 % 1 с) і рух < 25 % → 50 % (4M);
- інакше → 25 % (2M), після 500 мс безперервно малих кадрів; не нижче 1 Мбіт/с.

Частка часу: 8M 33.6 %, 4M 17.8 %, 2M 48.7 %; перемикань ставки за 60 с: 20.

| сегмент | 8M | 4M | 2M |
|---|---|---|---|
| drag | 18 % | 67 % | 16 % |
| video | 18 % | 72 % | 10 % |
| idle | 33 % | 0 % | 67 % |
| scroll | 99 % | 0 % | 1 % |
| typing | 20 % | 15 % | 65 % |

## Хвиля 7: ОДИН безперервний енкод зі зміною ставки посеред потоку

`python3 bench/quality/lowmotion_live.py --seconds 60 --repeat 3` (потрібен `libx264-dev`): той самий
змішаний 60-с workload і та сама політика, але ОДИН енкодер libx264 (`bench/quality/x264live`) на весь
потік: ставка (і VBV maxrate/bufsize) міняється через `x264_encoder_reconfig` у кадрі, де її міняє
політика, а незмінені кадри енкодеру НЕ подаються (skip агента; pts лишає паузу видимою ратеконтролю).
Тобто перехідні процеси VBV/референсів тепер справжні. Варіант — лише «skip» (refine/тайли не моделювались).

| | МБ/год (3 повтори) | сер. Мбіт/с | p95 1с | max 1с |
|---|---|---|---|---|
| без стелі | 1149 / 1149 / 1149 | 2.55 | 11.56 | 15.48 |
| зі стелею | 884 / 888 / 887 | 1.97 | 6.25–6.32 | 10.09–10.12 |

Порівняно зі склейкою (852 МБ/год зі стелею): перехідні процеси додають ≈ +4 % (≈ 886). Без стелі
безперервний skip-енкод дешевший за склейку (1149 проти 1271), бо енкодер не кодує незмінені кадри.
Якщо додати внесок refine/тайлів зі склейки (+58 / +112 МБ/год), зі стелею виходить ≈ 0.94–1.0 ГБ/год —
на межі цілі. Досі x264 (не MS MFT) і синтетичний workload; трафік реального парку — лише M4.
