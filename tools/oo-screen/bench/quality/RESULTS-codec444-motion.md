# Q2/F8 — 4:4:4 у русі: VP9 profile 1 / AV1 profile 1 проти H.264 4:2:0 (СИМУЛЯЦІЯ)

> **СИМУЛЯЦІЯ.** Linux, програмні енкодери ffmpeg (libx264, libvpx-vp9, libaom-av1), корпус
> `bench/corpus/*-1080p.png` (4 кадри). Немає Windows-захоплення, апаратних енкодерів, декодування у
> Chrome. Підтримка VP9 p1 / AV1 High у Chrome (WebRTC чи WebCodecs) **НЕ ПЕРЕВІРЕНА**.

Відтворення: `python3 codec444_motion.py` (≈10 хв). Прокрутка 8 px/кадр, 30 кадрів @30 fps, CBR-подібно
(`b = maxrate = bufsize`), PSNR по кожному декодованому кадру проти джерела у Y'CbCr BT.709 4:4:4;
chroma = середнє Cb/Cr. «@matched» — H.264 у режимі CRF (без обмеження бітрейту), CRF підбирається
бісекцією, доки **фактичний** бітрейт H.264 ≥ фактичного бітрейту 4:4:4-кодека (останній стовпець —
відношення H.264/4:4:4 по 4 кадрах; ≥ 1.00 = справді вирівняно). Попередня версія ставила H.264
`-b:v` = фактичному бітрейту 4:4:4, але libx264 CBR недобирає ~50 %, тож «@matched» мав на 20–100 %
менше біт — ті числа були завищені на користь 4:4:4 і замінені.

Найгірший кадр корпусу `colortext-1080p` (кольоровий текст): H.264 30.1/30.6 dB, VP9 p1 38.4/40.9 dB,
AV1 p1 45.3/46.7 dB (@4M/@8M ціль).

Висновки:
- **AV1 p1 4:4:4** (libaom realtime, cpu-used 8): chroma **+12.7 dB (@4M) / +14.0 dB (@8M)** проти H.264
  при справді вирівняному фактичному бітрейті (H.264 ≥ AV1 на 1–5 %). Luma у такого H.264 *вищий*
  (48.6/50.3 проти 45.2/47.4 dB) — AV1 виграє лише в кольорі. Середнє 51–52 dB ≥ цілі Q2 (50 dB), але
  найгірші кадри 42–43 dB і `colortext` 45–47 dB — **ціль не досягнута на всіх кадрах**. Кодування
  ~19–21 мс/кадр 1080p (процес ffmpeg, одна машина, не агентне залізо) — на межі 30 fps.
- **VP9 p1** (libvpx realtime): chroma +4…+6 dB, але бітрейт перевищує ціль у 1.8–2.5×, і H.264 навіть
  при CRF≈1 не набирає стільки біт (відношення 0.39–0.86, тобто рядок «@matched VP9» НЕ вирівняний —
  H.264 там отримує *менше* біт; чесного порівняння за рівного бітрейту немає). Не рекомендовано.
- H.264 у CBR-режимі сам недотягує до цілі (2.9 Мбіт/с при 4M) — «@matched» показує, що chroma H.264
  майже не росте з бітрейтом (+0.5…+1.2 dB при 1.0–1.9× біт; стеля 4:2:0 ≈ 38–39 dB у русі).
- Прототип переговорів: `internal/codec444` (Go) + `desktop-oo-codec444.js` (плеєр, WebCodecs probe),
  за замовчуванням вимкнено → H.264. Медіашлях агент→хаб→плеєр **не переведено** на VP9/AV1:
  потрібен власний транспорт + WebCodecs-декодер у плеєрі (див. STAGE3-444.md).
